# Trade news rules
- Trade-news links render through `EnlaceNovedad`: plain `<a target=_blank rel=noopener noreferrer>` for web pages, PDFs in the shared `VisorPdf` fed by the staff server fn `leerPdfNovedad` (fetches only the stored URL of an RLS-readable row) plus an official-site link; `enlace_estado` comes from server-side checks (daily review, "Verificar enlaces", retry, PDF fetch) where 401/403/429 count as restricted, not unavailable, so bot-blocking sites keep working links.
- Trade news come from admin-managed `fuentes_novedades`, reviewed by `novedades-comercio.server` (daily pg_cron → `/api/public/novedades/revisar` gated by a DB-only private token, or admin server fn): deterministic RSS/HTML link extraction, dedupe by SQL `novedad_url_clave` and, for the same `novedad_documento_clave` (host + linked file name, mirrored by `claveUrl`/`claveDocumento`), only when the stored fingerprint (`documento_bytes` + `documento_sha256` of the content without volatile PDF metadata via `sha256Contenido`; hash decides, size is the fallback, unknown counts as duplicate and is retried next run) matches — across saved, discarded and same-batch rows, with a unique index on (clave, sha256) and manual saves checked server-side by `comprobarDocumentoNovedad` — because official sites republish one notice under new media folders but also reuse file names for different documents, bounded sources/items with one AI call per source, single-flight lease and persisted pause on AI credit/access errors. Every source read (cron or manual) appends one `fuentes_novedades_intentos` row (success, state, HTTP code, mode; pruned after a year) so intermittent vs permanent failures are visible; a missing publication date is never replaced by the capture date — `textoFechaNovedad` renders "no disponible; registrada en la plataforma" for both the list and the assistant prompt.
- Trade news classification (impacto, sectores, relevancia) is produced in the same AI call that summarizes each new item and normalized against the shared catalogs; `ajustarRelevancia` deterministically downgrades an AI «Alta» lacking the criterion signals (mandatory change, in force/upcoming, affects agency sectors, eligible impact). Rows store `clasificacion_criterio`; the re-evaluation server fn only touches rows with an older/NULL criterion and `clasificacion_manual = false` (set when an admin edits the classification), so manual corrections are never overwritten. The Panel shows Alta by default; including Media is a per-user `preferencias_usuario` flag. The Operations «Novedades relevantes» block reads through `novedades-panel` (RLS-bound) using `novedadEnPanel`, and «Vista» is a per-user `novedades_vistas` row that never deletes or alters the news item.
